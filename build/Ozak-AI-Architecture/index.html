Ozak AI Architecture

Ozak AI separates the work of prediction from the proof of it. Four layers move data from ingestion to insight, the Ozak Streaming Network, the Data Vaults, Neuron, and Eon, each scaling horizontally across a network of independently operated nodes. A fifth, the Smart Contract Execution Layer, coordinates and settles them without ever sitting in the latency path. The result is a forecasting system where speed and auditability are not traded against each other.

1. Architectural Overview​

Ozak AI is built as five cooperating layers. Four of them do work; one of them keeps score.

2. Ozak Streaming Network (OSN)​

What it does: OSN is the system's gateway to the financial world. It ingests high-speed streams from on-chain and off-chain sources, normalises them, and hands clean data to the Vaults.

How it works:

  • Ingestion runs over exchange APIs, RPC and indexer endpoints, macro feeds, news wires, and social streams.
  • Apache Kafka manages the stream topology, giving durable, replayable, partitioned delivery that survives network disruption.
  • Apache Flink handles real-time processing - complex event processing, filtering, enrichment, windowed aggregation, and schema normalisation.
  • Horizontal scaling is the default posture. As throughput grows, relay nodes are added rather than existing nodes being upsized.
  • Validation before propagation. Relay nodes attest to data authenticity before it enters the system, which keeps malformed or adversarial feeds out of the model path.

3. Ozak Data Vaults​

What it does: Once data is processed, it needs a safe place to live. The Vaults are cryptographically secured, decentralised storage that act as the library Neuron reads from.

How it works:

  • Encryption at rest across all datasets, with keys held outside the storage plane.
  • Fragmentation and distribution. Data is sharded and replicated across multiple storage nodes, so no single node holds a complete or readable copy.
  • Redundancy guarantees availability when nodes go offline, and makes tampering detectable rather than silent.
  • Access control enforced by smart contract. Grant and revoke rules live on-chain, so permissions are verifiable rather than trust-based.
  • Retrieval is optimised for inference. Prediction Agents need low-latency reads on wide, sparse, heterogeneous datasets, so the Vaults combine structured stores with vector and document stores rather than forcing one engine to do everything.

4. Neuron - The Predictive AI Layer​

What it does: Neuron is the brain. It turns a natural-language question into a quantitative forecast with a confidence score attached.

4.1 Domain Relevance and Intent Mapping​

Every query passes a two-stage filter before any compute is spent on it.

  • Intent classification maps the query into a defined intent set - technical analysis, unlock events, market prediction, sentiment assessment, event calendar.

  • Domain alignment is verified by cosine similarity against domain prototype embeddings, and rejected below a threshold.

This dual-layer check does two things: it keeps precision high on intent routing, and it stops the system from confidently answering questions that fall outside its competence.

4.3 Prediction Agents​

Prediction Agents (PAs) are the user-facing wrapper around the model bank. Each PA is built on TensorFlow and PyTorch, trained with supervised and unsupervised techniques, and configurable on datasets, parameters, asset classes, and risk tolerance - so a momentum agent and a value agent can run side by side against the same underlying models.

5. Agentic Orchestration Layer​

What it does: A single forecast is rarely a full answer. The orchestration layer coordinates specialist agents and merges their conclusions into one coherent, confidence-weighted response.

Standing agents:

  • Prediction Agent - executes TFT, Helformer, and SegRNN forecasts
  • Technical Agent - evaluates market indicators and price structure
  • Sentiment Agent - aggregates social and on-chain sentiment
  • Event Agent - detects unlocks, protocol updates, announcements

Coordination is a graph, not a pipeline:

Vertices are agents, edges encode dependencies, and the aggregation function M produces a contextually consistent, confidence-weighted result. The graph structure is what enables parallel inference, cross-domain dependency handling, and confidence propagation - and it lets low-confidence branches trigger fallbacks instead of shipping a weak answer.

5.1 Custom Agents​

Users can instantiate their own agents, which then join the same graph as first-class participants:

A custom agent can depend on standing agents. For example, an agent monitoring DeFi unlock events can consume the Sentiment Agent's output to generate short-term volatility calls. Agent logic is iteratively refinable - data streams, forecast horizons, and thresholds can all be adjusted without rebuilding the agent.

5.2 Confidence Metrics and Guardrails​

Every agent emits a confidence score, and those scores propagate all the way to the user rather than being collapsed into a single number.

Operational guardrails block off-domain predictions, purely speculative outputs, and anything that reads as an implied financial guarantee.

6. Eon - Interface and Reasoning Layer​

What it does: Eon is your control panel. It's where you ask questions, watch agents, and read results.

How it works:

  • LLM reasoning sits above the agent graph. Plain-language queries are parsed, decomposed, and mapped into multi-agent workflows; quantitative agent outputs come back as interpretable narrative.

  • Conversational depth. Follow-up queries, scenario simulations, and comparative analyses are supported, so complex multi-dimensional relationships are explorable without technical expertise.
  • Confidence is surfaced, not hidden. Forecast probabilities, trends, and confidence metrics are shown alongside every result.
  • Built on React.js for a responsive experience across devices, with interactive charts, personalised dashboards, and direct smart contract interaction.

7. Smart Contract Execution Layer​

What it does: The Smart Contract Execution Layer sits at the centre of everything. It doesn't run the AI - it records and verifies every important action in the ecosystem, and it pays the people who did the work.

Contract set:

ContractResponsibility
Task OrchestrationAssigns work to AI, Data, and OSN nodes based on demand and available resources
PaymentDisburses rewards trustlessly against verifiable contributions - uptime, storage, compute, relay
StakingHolds node collateral; slashes on dishonest or unmet obligations
User AuthCryptographic identity and permission verification
User DataData proofs and Hashes, metadata commitments, redundancy incentives
ReferralEcosystem growth incentives

Cost posture: the layer uses rollup technology, bundling many operations into single on-chain transactions. This matters because the economic model depends on frequent micro-transactions for work and payments - without batching, the coordination cost would exceed the value of the work being coordinated.

8. DePIN Node Topology​

What it does: The whole platform runs on a Decentralized Physical Infrastructure Network - a community-owned network of machines instead of one company's servers. Three node classes, three hardware profiles.

NodeLayerRequirementFunction
Inference NodeAI LayerHigh AI compute - GPUs, specialised acceleratorsExecutes model inference and agent reasoning
Storage NodeData LayerHigh storage capacity, high availabilityHolds encrypted, fragmented public and private data
Relay NodeOSN LayerHigh bandwidth, low latency, reliable connectivityBridges on-chain and off-chain data into the system

Why decentralisation is load-bearing here, not decorative:

  • No single point of failure. Data survives node outages because it's replicated across the storage plane.
  • Censorship resistance and open participation. Anyone with suitable hardware can contribute compute and earn rewards, which prevents a handful of operators monopolising the inference layer.
  • Tamper evidence. Fragmentation plus on-chain proofs mean data modification is detectable, not silent.
  • Economic honesty. Staking makes misbehaviour expensive; slashing makes it costly in practice.

9. End-to-End Request Lifecycle​

Putting it together - here is what happens between a question and an answer.

  1. Data aggregation - time-series, sentiment, events, and relational datasets stream in continuously through OSN, independent of any user request.
  2. Query intake - a natural-language question arrives in Eon; the LLM layer parses and decomposes it.
  3. Relevance gating - intent is classified and domain alignment is checked. Off-domain queries stop here.
  4. Model inference - TFT, Helformer, and SegRNN generate forecasts against features assembled from the Vaults and the OSN cache.
  5. Agent coordination - the orchestration graph merges predictive, technical, sentiment, and event reasoning, including any custom agents.
  6. Guardrail evaluation - confidence thresholds are applied; low-confidence branches route to fallbacks.
  7. Narrative synthesis - the LLM layer translates quantitative output into interpretable explanation with confidence metrics attached.
  8. Delivery - results reach the Eon dashboard with low latency and explicit confidence scoring.
  9. Settlement - inference receipts, storage attestations, and relay proofs are committed on-chain; contributing nodes are paid.
